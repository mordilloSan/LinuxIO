# Jobs, phase 1: host, launcher, relay and the first mutation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the job host, launcher, store, relay and submit CLI, and run `docker.update_container` through them as the first `Mutation`, so a job started from the browser survives logout, bridge death and a LinuxIO update.

**Architecture:** A per-uid `linuxio-jobs@<uid>.service` runs the handler registry in a session-less process and owns an in-memory `TaskService` plus an on-disk record per job. The per-login bridge opens one yamux session to its uid's host and forwards every `Mutation` stream unchanged; a socket-activated root launcher starts hosts; a `jobs submit` CLI lets timers, the boot reconcile and tests start jobs without a browser. Existing `Call`, `TaskRunner` and duplex routes keep working in the bridge during the migration.

**Tech Stack:** Go 1.27 (`encoding/json/v2`, `go-yamux/v5`, `godbus`), systemd template units, TypeScript/React with TanStack Query, Vitest, Playwright.

**Spec:** [docs/superpowers/specs/2026-10-26-jobs-design.md](../specs/2026-10-26-jobs-design.md). This plan covers spec section 20 phase 1 only. Phases 2 to 5 (moving the remaining tasks and long calls, the quick mutations, schedules, history UI) get their own plans once this one has landed, because each depends on the mechanism built here.

**Store note:** the spec's "generalised `durabletask`" is realised as a new `backend/common/jobs` package with the same mechanics (`filelock`, `atomicfile`, pruning) and the spec's record. Its two users move onto it in this phase (Docker in Task 10, the network bridge handoff in Task 11) and `durabletask` is deleted.

- Spec values: host idle exit after 60 s with 0 bridges and 0 running jobs; 256 running jobs per host; records fsync only on state changes of jobs older than 1 s; jobs completed in under 1 s are deleted unless failed; retention 30 days and 200 per uid; launcher waits 5 s for the host socket; protocol number `1`; sockets `/run/linuxio/jobs-launcher.sock` (0666) and `/run/linuxio/jobs/<uid>/host.sock` (0600).

## Review Focus

1. A bridge that cannot reach its host (launcher down, socket missing) must fail each mutation with `connection_unavailable` and keep serving reads; it must never execute a non-browser-bound mutation locally. Test in Task 9.
2. A second connection to a user's host from a different uid, or to the root host from a non-root uid, is closed before any frame is read. Test in Task 5.
3. A record left `running` by a host that crashed is marked `interrupted/crash` by the next host, never resumed as running, and never duplicated by a resend of its id. Tests in Tasks 1, 4 and 5.
4. The browser resends a mutation after `outcome_unknown` only if no snapshot frame has arrived; after the snapshot it reattaches with `tasks.watch`. A resend never starts a second job. Test in Task 12.
5. `tasks.list` and `tasks.events` in the bridge must include both bridge-local tasks (uploads) and host jobs, with no duplicate and no lost terminal event when the host connection drops mid-stream. Test in Task 9.
